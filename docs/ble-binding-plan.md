# BLE 副屏绑定与防串连

## 目标与范围

一块 ESP32 LCD 只接受一台经用户确认的 Mac 的 BLE 数据。首次绑定需要触摸屏操作和系统验证码确认；后续自动重连。Mac 可以选择多块副屏。同步内容、经典蓝牙 Android 协议和 USB 数据帧保持兼容。

## 用户流程

1. 新固件首次启动为未绑定且禁止配对；屏幕的「连接管理」始终可用。
2. 用户在屏幕点击「开始配对」，开放 120 秒配对窗口。屏幕立即显示本窗口的随机六位码。Mac 启用同步，扫描后点击目标设备的「连接并配对」。系统弹出蓝牙配对输入框，输入屏幕显示的随机六位码。
3. ESP32 使用 BLE Secure Connections、MITM 验证、128 位链路加密和持久 bonding。认证前不处理用量和心跳。成功后关闭配对窗口，保存唯一主机。连接管理突出显示「已连接：Mac 名称」；断开后显示「已绑定：Mac 名称」并提示等待重连。主机名来自经认证连接，持久保存在 NVS，状态栏与底栏同步展示。
4. 设备和 Mac 重启、休眠或掉线后保留绑定；Mac 仅重连明确选择过的外设 UUID。ESP32 拒绝其他主机，不能因为超时、重复配对或旧版客户端连接而自动换绑。
5. 换绑：在屏幕「连接管理」中二次确认解除绑定，断开当前会话、清除密钥和旧数据显示，再开放配对窗口。若 macOS 留有旧密钥，按提示在系统蓝牙设置忽略旧设备后重试。
6. Mac「忘记」只移除本应用自动重连选择，不声称删除 macOS 系统密钥或解除屏幕绑定。

## 协议和兼容

- Nordic UART Service、RX 002、TX 003 保留。LCD RX 写入要求加密、认证，且对每次写入检查当前绑定身份。
- 新增 004 受保护的绑定特征：受保护的 read 返回协议版本与持久设备 ID；Mac 先 write-with-response 发送 authenticate 请求，由外设显式启动系统加密配对。完成配对后，Mac 读取身份，再写入主机显示名。只有身份读取及主机名写入确认都成功才发用量数据。
- Mac 首次发现仅列出，明确点击后才连接；未知 LCD 缺少安全特征时拒绝推送，提示升级固件。其他 BLE 副屏可手动选择继续旧协议，不自动连接。
- Mac 的外设 UUID 只用于本机重连选择；ESP32 实际信任 BLE bonding 密钥与身份地址。主机名和设备名不作为认证依据。
- 设置页按实际通道展示状态：经典蓝牙已连接时显示「已连接」与「经典蓝牙 · SPP」，隐藏该设备旧的 BLE 错误，停止重复 BLE 连接；只有 LCD 显示「连接并配对」。连接中禁用重复点击。经典连接建立后即使 BLE 广播停止，设备行仍保留。设备名称匹配仅用于合并展示和抑制多余连接，不参与认证。
- 「立即推流」读取当前用量，同时发送到所有已连接的经典蓝牙与 BLE 副屏。
- USB 是物理接入的数据通道，不创建/覆盖 BLE 绑定；USB 与 BLE 分开组帧，避免片段混合。BLE 断开/换绑后丢弃上一会话残片和队列数据。

## 验收

- 未选择设备不连接；未开启配对窗口无法新配对；验证码错误/取消不推送。
- 只有加密、认证、已绑定的主机会话能写入；旧客户端、其他主机、重复配对不能替换绑定。
- 重启保留绑定并能重连；换绑后旧主机不能写入，屏幕清除旧数据。
- Mac 与 ESP32 编译通过；策略测试覆盖上述拒绝矩阵；接入硬件验证广播、未授权拒绝、配对、推流和重连。需要用户输入屏幕验证码的环节如未执行，必须明确标记。
